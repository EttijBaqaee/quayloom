# Quayloom · 0.3.6

[![简体中文](https://img.shields.io/badge/简体中文-当前页面-blue)](README.md) [![English](https://img.shields.io/badge/English-Readme-lightgrey)](README.en.md) ![License](https://img.shields.io/badge/license-AGPL--3.0--only-green) ![Node.js](https://img.shields.io/badge/Node.js-24%2B-339933)

**把 AI 对话和生成任务留在自己的服务器上。**

Quayloom 是一款可自部署的多供应商 AI 聊天工作台，基于官方 [chat-demo](https://github.com/deepseek-ai/chat-demo) 界面开发。管理员集中配置模型服务、分发使用码和控制额度；使用者在电脑或手机上登录同一实例，即可继续自己的对话。刷新、关闭网页或退出登录，不会主动停止已经提交的生成任务。

- **服务端会话与后台生成**：对话和任务状态集中保存，跨设备访问，刷新后恢复进度。
- **多供应商接入**：支持 OpenAI Chat Completions / Responses、Anthropic Messages 和 DeepSeek 扩展，按模型配置能力。
- **管理员后台与使用码**：集中管理渠道、密钥、模型、授权、并发、请求次数和 Token 额度。
- **对话与统计**：流式输出、推理、消息分支、Markdown、公式、Mermaid，以及基于上游真实用量的统计。
- **中英文与明暗主题**：登录、聊天和后台支持中文 / English；浅色、深色或跟随浏览器，默认跟随浏览器。
- **自部署与移动访问**：提供 Docker / 1Panel 部署方式，支持子路径和 Android WebView 客户端源码。

## 功能

- 流式聊天、消息分支、Markdown、公式、Mermaid、历史 ZIP。
- 登录页、聊天页和管理后台均可切换中文 / English；手机聊天入口位于右上角工作台菜单。界面语言首次按浏览器语言选择，不翻译用户内容或供应商、模型名称。
- 浅色 / 深色 / 跟随浏览器三种主题，默认跟随浏览器并实时响应系统变化；语言和主题在当前浏览器持久保存、跨同源标签页同步，不随退出登录清除。
- 管理员管理供应商、Base URL、API Key、模型、能力和默认模型；供应商与模型在输入框底部选择。
- 支持 OpenAI Chat Completions 兼容、Anthropic Messages、DeepSeek 原生扩展；提供 DeepSeek、OpenAI、Anthropic、OpenRouter、Ollama 和自定义预设。
- 独立使用码登录，管理员配置到期、获准渠道和模型；登录输入静默清理首尾空白，不改变中间字符。
- 管理员在每个供应商的“渠道并发与配额”设置渠道并发上限（1–32，默认 4），管理员和所有使用码共享；达到上限时拒绝新请求，不排队、不重发，降低上限不停止已运行任务。
- 按 **使用码 × 渠道** 独立限制请求数、每日/累计聊天 Token 和并发，并受渠道总上限保护。
- 管理页用量分析按上海日期、渠道、模型和身份筛选已保存任务，显示真实用量、缺失覆盖率、每日趋势、分组和分页明细；与配额保守预留分开。
- **服务端持久会话与后台生成**：刷新或离开聊天页面不停止已提交的任务，返回时恢复部分内容和状态；相同任务重试不会重复发起上游请求。
- 管理员聊天页的 **使用码对话** 按钮可只读查看其他使用码的服务端会话与生成状态，不切换身份、不修改消息。
- 站内公告：管理员通过“发布通知”向全部使用码（含以后新建的码）或指定使用码发布；使用者通过“通知”查看未读/已读并标记已读，管理员可撤回。页面约每 30 秒更新；最多保存 1000 条（含已撤回），不发邮件、短信或系统推送。详见[使用码说明](docs/ACCESS_CODES.md)。
- HttpOnly / SameSite=Strict 登录 Cookie；供应商密钥在服务器 AES-256-GCM 加密保存，不回传浏览器。

## 源码启动

需要 Node.js 24+ 和 pnpm 11.28.5。

```sh
pnpm install --frozen-lockfile
pnpm type
pnpm lint
pnpm build
cp .env.example .env
pnpm start
```

默认地址为 `http://127.0.0.1:3210`，管理页为 `/admin`。首次初始化时通过 `ADMIN_PASSWORD` 或 `ADMIN_PASSWORD_FILE` 设置 12–1024 字符的密码；两者不能同时设置。不设置时，服务器会在首次启动终端显示一次随机密码。不要将真实凭据、环境配置或数据目录提交到 Git。

开发时分别运行 `pnpm start` 和 `pnpm dev`，访问 `http://localhost:8090`。不能双击 HTML 或仅使用 GitHub Pages 等静态托管运行本项目；生产需要 Node 后端。生产后端无第三方运行依赖。

本公开源码范围不包含内部测试、验证脚本、截图和验收日志。`type` 与 `lint` 仅为静态检查，不代表真实供应商能力或收费已验证。

## Docker / 1Panel 部署

### Docker Compose

需要 Docker Engine 和 Compose v2。在源码根目录复制环境模板：

```sh
cp .env.example .env
```

编辑 `.env`，填写实际域名；例如：

```dotenv
PUBLIC_ORIGIN=https://chat.example.com
COOKIE_SECURE=true
```

然后构建并启动：

```sh
docker compose up -d --build
docker compose logs quayloom
```

首次启动时在日志中读取一次性生成的管理员密码，访问域名下的 `/admin` 登录。也可在首次初始化前配置 `ADMIN_PASSWORD_FILE`，并在编排中只读挂载密码文件；不要将真实密码写入 Git。数据保存在独立 Docker 卷中，**不要使用 `docker compose down -v` 删除数据卷**。

编排默认仅发布 `127.0.0.1:3210`，需使用 Nginx 等反向代理对外提供服务。仅在服务器本机体验时，可设置 `PUBLIC_ORIGIN=http://127.0.0.1:3210` 和 `COOKIE_SECURE=false`，访问 `http://127.0.0.1:3210`；另一台设备不能通过它自己的 `127.0.0.1` 访问服务器。

### 1Panel

1. 将完整源码放到服务器项目目录，不要只复制编排模板。
2. 在项目目录准备 `.env`，配置准确的 `PUBLIC_ORIGIN`、Cookie 和可选子路径。
3. 在 1Panel 的容器编排中导入项目的 `compose.yaml`，确认构建上下文指向完整源码目录；按当前面板版本载入项目环境变量后构建并启动。
4. 在网站设置中添加反向代理到 `127.0.0.1:3210`，保留 Host 和完整路径；详细参数见[部署说明](docs/DEPLOYMENT.md)。
5. 查看容器健康和首次密码，登录后台添加供应商及模型。

### 子路径与离线镜像

部署到 `/Quayloom` 时，在 `.env` 设置 `BASE_PATH=/Quayloom`；仓库编排会把它同时传给构建参数 `APP_BASE_PATH` 和运行变量 `BASE_PATH`。`PUBLIC_ORIGIN` 只填写源，例如 `https://chat.example.com`，不含路径。修改子路径后必须重新构建前端。

如已获得离线镜像，可用 `docker load -i <镜像文件.tar.gz>` 导入，再把编排的 `image` 改成实际标签，并移除 `build` 配置。仓库不内置大体积镜像，也不预设已发布的容器 Registry 地址。

单独构建镜像可用 `docker build -t quayloom:local .`。本项目不启用 GitHub Pages 或自动推送镜像工作流。

环境变量完整示例见 [`.env.example`](.env.example)，备份、升级及反代配置见[部署说明](docs/DEPLOYMENT.md)。

## 接入供应商

1. 登录管理页，添加供应商并选择协议或预设。
2. 填写 Base URL 和 API Key；留空保存会保留已有密钥，明确勾选清除才会删除。
3. 可发现模型后选择加入，或手动填写真实模型 ID；能力开关需按服务商实际支持设置。
4. “连接测试”仅验证模型列表接口与鉴权，不保证推理、文件、语音或搜索可用。
5. 设置默认模型，返回聊天页选择供应商和模型。

Ollama 等内网模型仅在确有需要时启用“允许私网”。容器内的 `127.0.0.1` 指容器本身。元数据、链路本地等危险目标始终被拒绝；DNS 校验结果固定到实际连接，禁止重定向。

| 协议 | 范围 |
| --- | --- |
| OpenAI 兼容 | 按模型选择 Chat Completions 或 Responses；支持文本、推理和声明支持的图片；Responses 可显式配置原生 web_search；Chat Completions 不支持原生搜索 |
| Anthropic | Messages、声明支持的视觉/文件与 thinking；可显式配置原生 web_search_20250305；过滤 DeepSeek 专属扩展 |
| DeepSeek 扩展 | 对应官方域名和扩展协议；搜索、语音仍要求上游服务及模型支持 |

OpenAI 兼容图片由管理员上传到服务器，以身份和供应商隔离存入同一 SQLite 数据库；请求发出前按协议转换为 Chat Completions 的 `image_url` 或 Responses 的 `input_image`。支持 PNG、JPEG、GIF、WebP，单图最多 3 MiB，单身份最多 256 张且合计 128 MiB。图片随数据库备份；访问码仍仅支持文本。OpenAI 与 DeepSeek 思考强度跟随模型声明的支持列表，或使用渠道默认；DeepSeek 原生使用 `output_config.effort`（low/high/max），按登录身份、供应商和模型保存；关闭思考时不发送强度字段。未配置协议的旧模型继续使用 Chat Completions；不会因模型名称自动换协议或失败后自动重发。Responses 兼容省略 `response.created` 的合法进度或内容起流；非标准 `response.metadata` 仅作无内容旁路，不计用量、不代表成功。仍严格校验真实响应身份、完成输出与真实用量，断流或失败不会补造成功。

管理员聊天的原生联网搜索需要渠道真实支持：OpenAI 模型先选择 Responses，再选择“OpenAI Responses · web_search”；Anthropic 选择“Anthropic · web_search_20250305”，然后勾选联网搜索能力。新发现模型不会自动启用。仅打开聊天输入框的搜索开关时声明非 DeepSeek 搜索工具；搜索动作、来源与引用随会话保存。打开网页和页内查找仅展示上游实际返回的数据，本应用不抓取网页，也不执行任意工具。搜索可能单独计费，不包含在本地聊天 Token 额度中，应另设供应商预算。搜索适配不保证第三方兼容中转支持；失败不会自动切换协议或重发。使用码仍仅开放文本与推理，不开放搜索/文件/语音工具。

能力开关不会使上游自动支持功能。切换供应商不会转发另一供应商的文件 ID 或签名上下文。未接入 Gemini、AWS/Vertex、DSH OAuth 或设备登录，不读取 DSH 账号令牌。

## 会话、权限与费用边界

对话正文和生成任务保存在服务器，按管理员或使用码身份隔离；管理员具有只读查看使用码会话的权限。使用码仅支持文本与推理聊天，详见 [使用码说明](docs/ACCESS_CODES.md)。OpenAI 图片的服务器引用可随会话跨设备使用；浏览器中的个人设置、界面缓存和原始附件仍保留在当前设备。旧浏览器历史在对应身份第一次打开新版时迁移，已有服务器会话优先。

刷新、关闭页面或仅退出登录不会主动取消已提交的后台任务；点击“停止”会取消。使用码到期、停用或授权编辑会取消该码任务。任务最长运行十分钟；单身份最多保存 2000 条会话，单会话最大 4 MiB。服务器重启会将未完成任务标为中断并保留收到的部分，**不会自动重发可能已计费的请求**。新页面打开时会恢复任务状态；已打开的其他页面不是协同编辑器，写入冲突会拒绝覆盖。

配额在发送前预留，完整 usage 到达后结算；已经发往上游但失败、断流、缺少可靠 usage 或进程退出时保守扣减预留。每日默认按 `Asia/Shanghai` 重置。文件和语音计入请求及并发，但不计聊天 Token；本地配额不是货币预算或供应商余额，仍应在供应商侧设置硬额度。

## 统计与指标口径

会话页提供“对话 / 统计”切换；输入框下方的输出速度、缓存命中和圆形上下文占比均可点击查看详情，支持键盘、Esc 和点击外部关闭。管理员的“使用码对话”也提供只读统计，不会替用户发起或停止任务。

- 每行是一次服务端生成任务（一个模型步骤）；发送、重新生成、继续生成分别记录，刷新不会丢失，旧历史不根据字数补造统计。
- 输入、输出与缓存用量只采用供应商报告。输入总量包含普通输入、缓存读取和缓存创建；缓存命中率为缓存读取 / 输入总量。未报告与明确报告 0 不同，未知显示“—”；缓存详情中的未命中输入为输入总量减去缓存读取（包括缓存写入）。
- 首 Token 为服务器收到第一个非空文本或推理片段的等待时间。生成中与完成后，输出速度优先使用上游真实输出 Token / 首个至最后一个有效输出片段的观测时段；缺少真实 Token 速度时，至少两个有效输出片段形成时段后，明确显示“字符/秒”：文本与推理输出的 Unicode 码点数 / 首次字符输出至当前观测的时段（完成后止于末次字符输出）。字符≠Token，绝不据字数估算 Token。首输出前显示“等待输出”，已有输出但暂无有效时段显示“生成中”；未知值保持“—”，不转成 0。它们是服务器观测速率，不是 GPU 纯解码基准。活动任务约每 500ms 串行刷新，隐藏页面暂停轮询。
- 模型用时包含首 Token 等待和供应商内部无法拆分的处理；总用时另含服务器任务开销。当前没有本地工具执行器，工具用时显示“—”，不以 0 冒充已测量耗时；工具详情仅显示实际收到的名称，不暴露参数、结果或原始请求头。
- 上下文占比是本任务实际输入 / 管理员在模型配置中填写的“上下文窗口 Tokens”；没有占比但已知输入时，紧凑栏显示“上下文{输入数} Token”。详情区分“未配置窗口”“等待上游用量”“未返回用量”；不猜测模型上限，不为旧历史回填百分比，也不伪造系统提示词、工具定义、对话消息的 Token 细分。占比可能超过 100%，圆环仅在视觉上封顶。
- 运行、停止、失败和重启中断均保留独立任务记录；重启后的不可恢复计时保持未知，不把停机时间计入生成时间。统计不是供应商账单或余额，也不替代配额的保守结算规则。

界面和统计词汇参考 DSH 的统计面板及开发者工具说明，独立实现，不包含 DSH 的调试器、任意代码执行或敏感网络捕获功能。

## 数据和备份

服务器使用 SQLite 单进程独占锁，禁止多个副本共享同一数据目录。`data/` 包含数据库、加密主密钥和敏感会话。升级前停机，整体备份数据与主密钥；若使用 `STUDIO_MASTER_KEY`，须独立安全备份相同的 32 字节 Base64 密钥。丢失或换错主密钥无法恢复加密凭据。

历史 ZIP 只包含会话与本地可用图片，不包含 API Key、设置或非图片原件。导入会替换当前身份的历史，不会替换其他身份。原有管理员手动快照功能与自动持久会话不同，不应替代数据库备份。

重置密码前先停止服务，设置 `RESET_ADMIN_PASSWORD`，执行 `pnpm reset-password`，清除该变量再启动；同时更新现有密码文件或配置。密码重置撤销已有登录，但不应作为取消后台任务的替代操作。

生产建议同源 HTTPS。HTTP 不提供传输保密性；服务端会话正文不是端到端加密。共用浏览器或不可信扩展可能读取本机缓存。

## Android 客户端

`android/` 提供轻量 WebView 客户端源码：填写工作台的 HTTP/HTTPS 地址，再使用使用码或管理员密码登录现有服务。它不是离线推理引擎，也不内置供应商密钥；服务端仍需独立部署。客户端不保存明文登录凭据。HTTP 不提供传输保密性，生产推荐 HTTPS。构建和安装方法见 Android 目录说明；源码存在不代表 APK 已通过实机验证。

<a id="faq"></a>

## 常见问题

**可以直接部署到 GitHub Pages 吗？** 不能。持久会话、后台任务、密钥和配额依赖 Node 后端及可写数据目录。

**为什么另一台设备访问不到 3210 端口？** 编排默认只绑定宿主机回环地址。请配置反向代理和准确的 `PUBLIC_ORIGIN`，不要误把另一台设备的 `127.0.0.1` 当成服务器地址。

**刷新网页会停止生成吗？** 不会主动停止已提交任务。任务由服务器执行；服务器重启会保留部分内容并标为中断，不自动重发可能已计费的请求。

**勾选搜索或文件能力后就一定可用吗？** 仍取决于供应商、模型和协议的实际支持。使用码目前仅支持文本与推理。

**可以多个容器共用同一数据库吗？** 不可以。本版本使用单进程独占 SQLite；独立实例必须使用独立数据目录和密钥。
