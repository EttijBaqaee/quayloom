# 使用码与独立渠道额度

## 登录入口

- 使用者打开 `https://your-domain.example/Quayloom/`，默认是“使用码登录”。
- 管理员打开 `https://your-domain.example/Quayloom/admin`，默认是“管理员登录”；首页也可切换登录方式。
- 管理员密码不能当使用码登录；使用码不能进入管理后台，也不能读取供应商密钥。

## 管理员发码

1. 先在管理页添加并启用渠道，配置模型及供应商 API Key。
2. 在“使用码管理”中创建码，填写名称和可选到期时间。时间输入使用当前浏览器时区，服务器按绝对时间执行到期。
3. 勾选一个或多个渠道/模型；点渠道可选择其当前全部模型。以后新增的模型不会自动获得授权。
4. **逐个渠道**设置此码的每日请求次数、每日 Token、累计 Token 和最大并发。前三项留空为不限，正整数才是有效上限；并发为 1–32，默认 4。
5. 保存后可显示、隐藏和复制原码。原码在服务器加密保存，列表默认隐藏；显示后 60 秒或页面隐藏时自动隐藏。HTTP 内网环境无法使用剪贴板 API 时会尝试复制回退，也可手动选中复制。
6. 只把使用码发给使用者，不要发管理员密码或供应商 Key。显示码的屏幕和剪贴板均应视为敏感信息。

## 渠道独立核算规则

核算维度是 **使用码 × 渠道**，不是使用码跨渠道共享余额。

例如同一码获准使用 A、B 两个渠道，A 每日 10 次，B 每日 20 次：A 用完 10 次以后，A 请求会拒绝，但 B 仍保留自己的 20 次额度。每日/累计 Token 和并发也分别计算，不在 A、B 之间挪用。一个渠道下的多个模型共用该码在此渠道的额度。

渠道自身还可配置工作台总上限：该渠道的所有使用码与管理员请求都计入这个总上限。总上限是额外保护，不会把不同渠道合并计量；任何一层先达到上限，都可拒绝请求。页面显示的是此码独立额度，不是供应商余额，也不保证供应商账户仍有余额。

- 每日计数按 `Asia/Shanghai` 日期重置；累计数不自动清零。
- 聊天开始前预留输入 UTF-8 字节数、消息开销与模型最大输出 Token，收到有效 usage 后结算。额度过小可能在输出前即被拒绝。
- 断流或进程重启缺少可靠 usage 时保守保留预留计量，因此并非精确供应商账单。
- 调整上限、撤销授权再重新授权，不会重置已产生的用量。
- 停用/到期使登录和请求失效；修改使用码会中止该码进行中的聊天。重新启用后，已撤销的会话不会自动恢复，需重新登录。
- 渠道停用、删除或模型移除，会使对应的新请求不可用；修改使用码时可清理不可用授权项。

## 使用者界面与数据边界

登录后，在输入框底部选择获准的渠道与模型；“我的额度”按渠道展示本码用量。使用者看不到未授权渠道，不能增改渠道、管理码或读取管理员服务器历史快照。

当前使用码仅支持文本和推理聊天，暂不开放图片、文件、语音、工具与搜索，避免跨身份附件/资源混用。管理员原有能力不因此取消。

对话正文和生成任务按身份保存到服务器，切换身份会重载页面。刷新或关闭聊天页不会停止已提交的生成；返回后恢复状态，不重复发起上游请求。旧本机历史在对应身份首次打开新版时迁移，服务器已有内容优先。附件原件仍是浏览器本地数据，不保证跨设备可用。管理员旧的手动快照功能独立保留。

管理员在聊天页点击“使用码对话”，可选择使用码、只读查看其会话、全部消息版本和实时生成状态。查看不会冒用该身份，也不能修改、删除或停止对方的任务。使用者无法访问该入口或读取其他身份的会话；使用者应知悉管理员可查看服务端对话。

这属于应用内隔离，不是设备级加密保险箱。共用同一浏览器资料、同源开发者工具或恶意扩展仍可能访问本机存储；敏感用户应使用独立浏览器资料。HTTP 内网传输不提供保密性，公网使用应启用 HTTPS。

## 站内公告

- 管理员在工作台点击“发布通知”，进入“站内公告管理”，填写标题和纯文本正文，选择“全部使用码（包括以后新建的码）”或“指定使用码”后发布。全体范围不是发布时的使用码快照；以后创建的码也可看到仍有效的全体公告。
- 指定范围按使用码身份选择，未被选中的码看不到该公告。标题最多 120 字符，正文最多 20000 字符，单条最多选择 1000 个码。
- 使用者在聊天页点击“通知（未读数）”，可分页查看发给本码的公告、逐条“标为已读”或“全部标为已读”。已读状态保存在服务器并按身份隔离；全标已读仅作用于当前可见范围。
- 保持登录且打开工作台时约每 30 秒刷新通知，管理员打开管理弹窗时也定期更新，均可手动刷新。轮询受网络和浏览器后台节流影响，不保证精确或即时送达。
- 管理员可确认撤回公告；撤回后使用者下次刷新不再看到它，但无法抹去已阅读、复制或截图的内容。撤回不删除服务器记录。
- 公告存量最多 1000 条，**包括已撤回记录**；达到上限会拒绝新发布，需要部署管理员安排归档维护，不会靠撤回自动释放名额。界面每页 50 条。
- 这是站内功能，不调用手机/桌面系统通知，也不发送邮件、短信或离线推送；关闭工作台后不保证提醒。此说明描述实现，不构成生产环境或 Android 设备已验证的声明。
