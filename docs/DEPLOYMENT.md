# Quayloom 部署

## 运行环境

需要 Node.js 24+。构建机使用锁定版本的 pnpm 安装依赖并执行 `type`、`lint` 和 `build`。生产运行文件包括构建后的 `dist/`、`server/`、`package.json`、`LICENSE`、`LICENSES/` 和 `NOTICE.md`；发布时还须保留与运行版本一致的对应源码 ZIP，并配置其受控下载入口。后端没有第三方 npm 运行依赖。不要把源码工作目录或数据目录作为静态目录暴露；公开源码应使用经过筛选、不含凭据的归档。

原生运行默认绑定 `127.0.0.1:9810`。使用反代时保留准确的 Host 和 Origin；`PUBLIC_ORIGIN` 必须是浏览器可见的完整源，例如 `https://chat.example.com`，不带末尾斜杠和路径。HTTP 只能用于可信环境，并设置 `COOKIE_SECURE=false`；公网推荐 HTTPS 和 `COOKIE_SECURE=true`。

## Docker / 1Panel

仓库提供多阶段 Dockerfile 与通用 `compose.yaml` 模板。在 1Panel 中导入完整项目并构建 `quayloom:local`，再创建容器编排；仅复制 compose 文件不够。设置 `PUBLIC_ORIGIN`、初始密码、挂载路径和持久卷后再运行。

容器以非 root `node` 用户运行；模板限制内存与 CPU、丢弃 capabilities、启用 no-new-privileges，并将监听端口仅绑定到宿主机回环地址。迁移旧绑定目录时只调整本项目专用目录的权限，禁止广泛 chmod。

首次初始化通过 `ADMIN_PASSWORD` 或只读挂载的 `ADMIN_PASSWORD_FILE` 提供 12–1024 字符密码；二者不能同时设置。未设置时，服务器在首次终端输出一次随机密码。密码不要写入 compose、镜像或 Git。已建库后，配置的密码必须匹配现有密码，修改环境变量不会自动重置。

## 子路径

生产入口与两个 compose 模板在 `BASE_PATH` 未设置或为空时默认使用小写 `/quayloom`。在编排的运行时环境中修改 `BASE_PATH` 并重建容器即可，**不必重新编译或构建镜像**；路径大小写与嵌套层级原样保留，例如 `/Quayloom`、`/nested/app`。已有显式 `BASE_PATH=/Quayloom` 的入口保持不变。反向代理必须匹配同一完整路径；`PUBLIC_ORIGIN` 只写源，例如 `https://chat.example.com`。

以下示例对应显式 `BASE_PATH=/Quayloom`（默认部署请改为 `/quayloom`）：

```nginx
location = /Quayloom { return 308 /Quayloom/; }
location ^~ /Quayloom/ {
    proxy_pass http://127.0.0.1:9810;
    proxy_set_header Host $http_host;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 660s;
    client_max_body_size 40m;
}
```

`proxy_pass` 末尾不能带 `/`，反代必须保留完整路径。Cookie 仅适用于配置的 BASE_PATH，根路径 API 不会绕过子路径授权。内部 `createApp()` 未传路径选项时仍以根路径运行，供内部测试使用，不改变生产入口的默认值。

## 独立网页搜索与获取

后台“网页搜索与获取”可分别选择 Search 和 Fetch 服务。初始搜索停用，获取使用带公共地址检查的直接 HTTP；保存配置不会执行检索，也不会自动启用任何模型的联网能力。

1. 选择 DeepSeek Search API，填写服务基地址和独立搜索密钥。默认基地址为 `https://api.deepseek.com/v1/tools`，服务器追加 `/search`；兼容服务必须支持相同请求与响应格式，不是聊天模型端点。
2. Fetch 可保留直接 HTTP，或单独配置兼容 DeepSeek Fetch API 的基地址和密钥，服务器追加 `/fetch`。两种服务不共用聊天模型凭据，也不自动互相回退。
3. 在 OpenAI 类型模型中显式选择“独立搜索服务”，再勾选“联网搜索”。Responses 和 Chat Completions 均使用普通 `web_search`、`web_fetch` 函数工具；模型渠道必须支持相应协议的函数调用。已有原生搜索选项保留，不自动切换模式。

搜索和远程获取由各自服务另行计费，不计入聊天模型 Token 额度；返回内容参与后续模型输入，仍会消耗模型 Token。一次聊天请求可能包含多个付费模型轮次；每轮先预留额度再发起请求，共享该请求的输出上限，缺少完整用量时不继续调用工具。当前最多 5 个模型轮次、4 次工具调用，每次搜索最多 3 个查询。

密钥加密存储，管理接口只返回是否已保存。输入留空保留旧值，明确勾选清除才删除；不要在聊天或日志中粘贴密钥。配置接口为 `GET/PUT /api/admin/web-tools`，PUT 使用 `{ "config": { "search": { ... }, "fetch": { ... } } }`，仅管理员可操作。

“允许访问私有网络”仅授权访问该检索服务本身的地址，不放开被获取网页的私网限制。网页获取仍拒绝回环、内网、元数据地址和混合公私 DNS；远程服务也必须自行限制目标与重定向。服务请求不跟随重定向，响应最大 512 KiB，每次工具操作限时 30 秒，投影文本最多 24000 字符。检索内容只作为不可信资料，不执行网页脚本。

## 会话和权限

生成由服务器后台任务持有，HTTP 轮询连接断开不取消上游。使用者点击停止或授权失效才取消；服务器重启不自动重发未完成任务。任务最长十分钟。部署升级会中断当时仍在运行的任务，最好安排维护窗口。

管理员可以管理供应商、读取使用码原文，并通过只读接口查看使用码的服务端对话。普通使用码只能读写本身份会话和使用获准模型；不能调用管理接口。对话正文不是端到端加密，数据库和备份必须按敏感资料保护。不要记录 Authorization、Cookie、请求体或环境密钥。

## 备份、升级和回滚

一个数据目录仅允许一个进程，禁止多副本共享 SQLite；不要打开第二个 SQLite 客户端读取正在运行的生产库。

1. 先完成独立构建，保留旧镜像引用、编排和环境配置。
2. 通过部署管理器停止且仅停止本项目，确认数据库不再运行。
3. 整体备份 `data/`、密码文件、原编排和主密钥。若使用 `STUDIO_MASTER_KEY`，独立备份相同的 32 字节 Base64 密钥。
4. 保留原挂载、密码和密钥，原位更新镜像，不创建第二个实例占用同一数据库。
5. 检查实际健康、登录、供应商配置、数据迁移和反代；部署 API 接受请求不代表升级已完成。
6. 回滚时配套恢复该版本兼容的数据备份，不承诺数据库可直接降级；不要删除唯一备份。

0.3 新增按身份隔离的持久会话和任务表。旧供应商、使用码、额度、管理员密码、主密钥与手动历史快照保留。浏览器旧历史在相应身份打开新版时迁移，已有服务器数据优先。浏览器附件原件仍需独立保留；数据库备份不包含这些本机文件。

0.3.11 为管理员 OpenAI 文档文本新增 `studio_documents` 表，复用同一数据库连接，按身份和供应商保存提取文本与元数据；无需外部转换服务或额外 Node 运行依赖。文档引用在上下文校验和额度预留前展开。数据库备份包含这些提取文本，但不包含浏览器原件。模型的文档能力必须在管理页显式开启，已有模型开关不自动修改。PDF 中文映射与字体通过应用自己的静态路径提供，反代必须同时放行完整构建目录；不要为解析器配置 CDN。

丢失或换错主密钥会导致启动失败，无法恢复加密供应商密钥或使用码。不要用新建数据库掩盖主密钥问题。

### 文档附件资源与恢复边界

- 文本/代码、CSV/JSON 必须使用 UTF-8，二进制控制字符会被拒绝。原件最多 10 MiB，提取结果最多 200000 字符且最多 1 MiB；超限拒绝，不静默截断。
- DOCX/PPTX/XLSX 的 ZIP 最多 2000 个条目，单条展开最多 4 MiB、总展开最多 20 MiB、压缩比最多 100 倍；ZIP64、分卷、加密、宏、嵌入对象及其他不支持的结构会被拒绝。PPTX 最多 200 张幻灯片，XLSX 最多 200 个工作表，每表最多 100000 行和 100000 个单元格。表格只取已有缓存值，不执行公式；原件小于 10 MiB 也可能因这些限制被拒绝。
- PDF 最多 200 页、全文件最多 100000 个文字条目，超限拒绝、不截断；不支持扫描件 OCR、加密文件或含 JavaScript 动作的文件。15 秒后终止解析 Worker 是时间限制，不是浏览器堆内存硬上限。即使逐批读取和计量提取文字，也只限制应用端累计文字；PDF 解析器内部解压、字体、交叉引用等操作仍可能产生较大峰值内存。不要将其描述为可严格限制任意 PDF 内存占用的沙箱。
- 每身份最多保存 256 份文档、合计 64 MiB 提取文本，跨该身份的所有供应商合计；引用读取仍按身份和供应商隔离。每次请求最多展开 100 个文档引用，提取文本连同包装文字最多 2 MiB，并继续受模型上下文限额约束；展开在上下文校验和 Token 额度预留前完成。
- 历史 ZIP 不包含服务器保存的文档提取文本，也不包含非图片原件，仅保留这些附件的元数据。跨实例迁移或文档表丢失时，不能仅靠历史 ZIP 恢复文档内容；需要独立保留的原件重新上传，或配套恢复完整数据库及原有身份/供应商配置。完整数据库备份包含提取文本，但不包含浏览器原件；恢复后仍须核对引用与权限，不能把另一实例的文件 ID 直接当作可用文件。

## 密码重置

先停止服务，设置 `RESET_ADMIN_PASSWORD`，执行 `node --env-file-if-exists=.env server/reset-password.mjs`，清除重置变量，并同步更新原密码文件或配置后再启动。重置撤销已有登录；后台任务的取消应通过正常停止或授权管理处理。

公开范围包含修改、构建、安装与运行所需的应用源码、锁文件、构建配置、许可和使用文档。内部测试验证、截图、报告、日志、生产部署细节、数据、凭据、Android 私有签名和构建产物不在此范围；测试文件仅留工作区，不应删除。私钥不得为满足源码提供要求而公开，Android 接收者可自行构建并使用自己的密钥签名。不提供 GitHub Pages 或自动发布镜像工作流；公开源码不等于已部署服务，也不表示已完成 APK 实机测试。
